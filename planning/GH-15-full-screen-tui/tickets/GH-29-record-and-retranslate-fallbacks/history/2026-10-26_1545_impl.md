# Implementation: record the fallbacks, and translate them again

Planned 2026-10-26 against `main` at `3ce6fc3` (0.3.0). Baseline: 322 tests pass, coverage 93.9%.

Rests on story decisions 008, 009 and this ticket's 001 (strip from `existing`), 002 (the record's shape), 003 (the
receipt unchanged).

- `src/i18n_ai/application/ports/locale/engine.py`: `FileTranslated` (gets `rejected`).
- `src/i18n_ai/application/ports/locale/store.py`, `__init__.py`: the pattern the record's port follows.

- `src/i18n_ai/domain/sub_domains/locale/entities/document.py`: `LocaleDocument` (gets `without`).
- `src/i18n_ai/domain/sub_domains/locale/entities/tree.py`: `LocaleTree.output`, `target_location`.
- `src/i18n_ai/infra/adapters/filesystem/locale_store.py`, `__init__.py`; `src/i18n_ai/di/platform/filesystem.py`:

## Steps

1. **`LocaleDocument.without(paths)`**: a copy without the messages at `paths`: an object's key is deleted, a
   list's item becomes `None` so the other indexes still hold. Missing paths are ignored. `reusable_translations`
   keeps only strings, so neither is reused.
   → check: `tests/domain/test_document.py` (new): nested key, list index, missing path, the original unchanged.
2. **`FileTranslated.rejected: Mapping[KeyPath, str | None]`**, default empty: each fallback's last rejected text,
   by path. In `assemble`, from `state["previous"]` for each failed unit (`None` when the model gave none).
   → check: a test in `tests/infra` (or the integration test below) sees `rejected` for the `Stubborn` gateway's unit.
3. **The record's port**, `application/ports/locale/fallbacks.py`: `FallbackEntry` (file: `PurePosixPath`, key:
   `str | None`, path: `KeyPath`, problems: `tuple[Violation, ...]`, rejected: `str | None`) and `IFallbackRecord`
   with `read(directory) -> tuple[FallbackEntry, ...]` (empty when there is no record) and
   `write(directory, entries)` (removes the file when `entries` is empty, writes nothing when there was none).
   Exported from `ports/locale/__init__.py`.
   → check: `uv run lint-imports` and mypy pass.
4. **The adapter**, `infra/adapters/filesystem/fallback_record.py`: `FileSystemFallbackRecord`, the format of
   decision 002 (`version: 1`, sorted by file, key, path; indent 2, UTF-8, final newline; `path` as segments).
   A record with another `version`, or not valid JSON, reads as empty with a logged warning (it is rewritten by the
   next run). Provided in `di/platform/filesystem.py`.
   → check: `tests/infra/test_fallback_record.py` (new): round-trip with a dotted Laravel key and a list index;
   sorting; empty → no file; a broken file → empty.
5. **The handler reads the record and strips it.** The record's directory is `tree.output`, or its parent when
   `tree.output` is a file (a bundle). Entries are matched to a job by the target location's path relative to that
   directory, and its `bundle_key`. In step 3, each existing document loses its recorded paths (`without`), also
   with `--overwrite` skipped (nothing is read then).
   → check: an integration test: after a partial run, a second run with a well-behaved gateway sends the fallback
   to the model (the fake gateway sees its unit) and writes the translation.
6. **The handler writes the record.** After the engine's loop (in the `finally`, so an interrupted run keeps what
   was written): for each `FileTranslated` that was written (`WRITTEN` or `PARTIAL`), its (file, key) entries are
   replaced by its fallbacks; `FAILED`, `REFUSED` and `IGNORED` leave theirs. Entries of files and locales the run
   did not touch stay.
   → check: integration tests: a partial run writes the record with `rejected` and `problems`; a run with no
   fallbacks writes none; the second run of step 5 empties it and the file is removed; a strict refusal leaves the
   record as it was; a run on one target keeps another target's entries.
7. **The scanner ignores the record.** In a file-per-locale tree and a Laravel tree, a `.i18n-ai-fallbacks.json`
   beside the locales is not a locale and not an error.
   → check: `tests/infra/test_tree_scanner.py`: both layouts with the record present scan as before. If either
   picks it up, skip dotfiles in `_file_layout`'s and `_laravel`'s globs.
8. **Docs.** `docs/guide/rules.md`: what a fallback is now (recorded, translated again by the next run, commit the
   record). `CONTEXT.md`: **Fallback record** under Generation.
   → check: `uv run sphinx-build -W docs docs/_build` (or the repo's docs check) passes.

## Tests

- Domain: `LocaleDocument.without`.
- Infra: the record adapter's format and its edge cases; the scanner with a record present.
- Integration (`tests/integration/test_generate.py`, through the mediator with the fake model): the record written,
  merged, emptied and removed; a recorded fallback translated again; strict and failed runs leave it.
- The existing fallback test keeps passing unchanged (the receipt is unchanged, decision 003).

## Risks

- **Every existing user's partial files:** fallbacks written before this change are not recorded, so they stay kept;
  only new runs record. Said in the docs; `--overwrite` is the way out.
- **A bundle's output path** (`tree.output` a file, or a directory holding `root.name`): matching entries by the
  target location's path relative to the record's directory covers both; the bundle test exercises it.
- **Laravel trees without a source file:** the target's keys are the source; stripping a fallback removes that key
  from `existing`, which must not change the source the scanner derived. The scanner reads before the handler, so it
  does not; the Laravel integration test is run with a fallback to make sure.
- **Concurrency:** one run writes the record once, at the end; two runs at once on one tree can lose entries, as
  they can already lose target files. Not handled.
