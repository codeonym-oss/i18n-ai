# Watch a TUI run live, retries and failures included

## Problem

The progress port takes a description string per finished file, and the engine says nothing until a file is done:
a run cannot show which file × locale is being translated, or its retries as they happen.

## The change

- The engine yields two new events: an atom started, and an attempt rejected (how many messages, which attempt of
  how many).
- `IGenerationProgress` takes typed events (started, retrying, done with its `FileResult`, dropped) instead of a
  description; the handler passes each on (story decision 004). The console adapter renders what it renders today.
- **Run screen:** each file × locale with its state (waiting, translating, retrying k/n, written, partial, failed,
  ignored), overall progress, and the failures as they arrive.

## Done when

- [ ] An engine test with the fake model sees started, retrying and done for an atom whose first attempt is rejected.
- [ ] The CLI's `generate` output is unchanged (its existing tests pass as they are).
- [ ] A `Pilot` test watches a run go from waiting to written, through a retry.
