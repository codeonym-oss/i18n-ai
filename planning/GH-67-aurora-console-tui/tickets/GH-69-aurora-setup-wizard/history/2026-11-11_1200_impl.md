## The design, point by point

`v2/Setup` of https://claude.ai/artifact/4YxKpWHpFawQL6crNdD1nF (version 1794384556-a439, read again 2026-11-11),
as far as decisions 001–005 keep it. Each point is checked against the snapshots in step 7.

- **Command bar:** the crumb reads "New run / Targets", the step's name after "New run /".
- **Header:** the step chips, joined by "──": a done step "✓ Tree" in mint, the current one with a violet dot and
  its number on a raised surface, the next ones muted. Then, on the right, Continue and the primary "Plan ⌃R".
- **Each step's title:** a bold line and a muted one under it: "Which tree?" / its path and layout; "Which
  locales?" / "From en · 323 CLDR locales · the ones in the tree first"; "Which model?" / the provider's state.
- **Search:** on the title's line, "⌕" before it, "N match" after it while it holds words; `/` focuses it.
- **Filter chips:** "All", "In the tree · 2", "Right to left", "Picked · 4"; the one on is raised.
- **Card:** the code bold (violet-light when picked), the RTL/LTR tag, "■" or "□" on the right; the name; the
  state, mint for "in tree · …", sky for "new · …". Picked: a raised violet surface and border; focused: a thick
  violet border.
- **This run:** a "THIS RUN" card, the picked locales as chips ("ar ×"), then three figures in tiles (files,
  locales, messages, decision 003's line drawn as the design's figures); a "MODEL" card: "● openai / gpt-4.1-mini"
  and "★ recommended" on its right.
- **Status line:** the section chip, then "step 2 of 3 · targets" (the screen's `status_tree`), then the key hints:
  `/` search, Space pick, ⌃R plan, Esc back.
- **Left out on purpose:** the native names (decision 003), the Options card and its toggles and context
  (decision 001), the "jobs" and "batches" figures (a batch count is the settings' guess, not the scan's), the
  sidebar's separate Setup and Plan entries (story decision 004 keeps Home, Run, Review).

## Steps

1. **The steps** (decisions 001 and 002).
   - `body()` yields a `#steps` header with three step chips (`#step-tree`, `#step-targets`, `#step-model`) and a
     `ContentSwitcher` (`#wizard`) of three panes:
     - `#tree-step`: `#tree` or `#tree-path`, `#source-row`, `#output`;
     - `#targets-step`: the cards (step 3);
     - `#model-step`: `#provider`, `#model`, the key row (step 4).
     The header, after the chips, holds **Continue** (`#continue`, hidden on Model) and `#next`, "Plan ⌃R", as
     the design draws them (see "The design, point by point").
   - Beside it, the `#this-run` panel (step 5).
   - A `step` reactive names the current pane; its watcher sets `#wizard.current` and the chips' classes (`-done`,
     `-now`). A step is done when its fields are filled: the tree scanned; a target picked; a model picked and its
     key set or not needed.
   - Clicking a chip opens its step; Continue opens the next; `escape` (a new binding, shown) opens the previous one,
     and does nothing on Tree.
   - **⌃R** (`action_plan`): when something is missing, it opens the first step that lacks it, and the warning names
     it ("Pick a target first."). Otherwise `_run`, as today.
   - → check: a Pilot test opens Model with a click on its chip before any target is picked, comes back with
     `escape`, and goes forward with Continue; another presses ⌃R with no target and finds Targets open and the
     warning shown.

2. **The step it opens on** (decision 005).
   - Once the first `_scan` ends: Targets when it found the source, else Tree (the source is asked). With no tree
     found, it stays on Tree. Only the first scan moves the step: a tree switched, or a source picked, leaves it.
   - → check: Pilot tests on the i18next example (opens on Targets), on a tree whose source cannot be told (opens on
     Tree, with the source row), and with no tree found (opens on Tree, with the path field). After a switch of
     tree from the command bar, the step is unchanged.

3. **The locale cards** (decision 003).
   - `kit/` gains `LocaleCard(code, name, direction, state, picked)`: a focusable widget showing the code, an
     RTL/LTR tag, the name and the state; the `-picked` class checks and outlines it; Space, Enter or a click posts
     `LocaleCard.Toggled`.
   - The coverage: once a scan finds the source, a second scan with the existing targets gives each existing locale's
     share done, as Home works it out (`reusable ÷ (reusable + to_translate)` over its files). A new locale's state
     is "new · N messages", N the source's messages.
   - `#targets-step` holds `#search`, the filter chips (`#filter-all`, `#filter-tree`, `#filter-rtl`,
     `#filter-picked`, their counts in their labels), and a `Grid` `#cards`.
   - `_show_targets` mounts at most 24 cards matching the search and the filter, in `locale_choices`' order, then a
     `#more` line "+N more · type to narrow" when more match. It replaces `SelectionList` `#targets`; the checked
     set stays `self._checked`, kept across searches as today.
   - `aurora.tcss`: `.locale-card`, its `-picked` and `:focus` states; `#cards` four columns, two under `-narrow`.
   - → check: Pilot tests: the i18next example shows fr's card first, picked, "in tree · 11% done" (3 of 26 messages); a search of
     "ar" shows ar's cards only and keeps fr picked; Right to left shows only RTL locales; with no search, the
     24th card is followed by `#more`; Space on a focused card picks it and the plan line counts it.

4. **The model card** (decision 004).
   - `kit/` gains `ModelCard`: provider, model and key state, built from what `_show_key` already works out
     ("✓ set (keyring)", "none needed", "key needed"; "no model yet" before one is picked). One sits at the top of
     `#model-step`, one in `#this-run`; both refresh when the provider, the model or the key changes.
   - The selects, the key, its keyring checkbox and their behaviour stay as they are.
   - → check: the existing tests `test_the_model_waits_for_its_provider_and_a_missing_key_is_asked`,
     `test_another_provider_clears_the_models` and `test_the_settings_model_is_the_default` pass; a new one checks
     the card says "key needed" for openai with no key, and "✓ set (for this run)" once the key is given.

5. **The "This run" panel.**
   - `#this-run`, a `Card` titled "THIS RUN": the picked locales as `Chip`s, the plan line (`#plan`: files · locales
     · messages, the messages from the second scan's `qualified` files), the model card, and the fallback line
     (`#fallbacks`, "N fallbacks recorded · v to review", shown only with some), moved there from the form.
   - Beside `#wizard` from `WIDE` columns, under it below (`-narrow`), as story decision 002 says.
   - → check: `test_the_form_starts_from_the_projects_preset` asserts `#plan` reads "2 files · 1 locale · N
     messages" (N counted by hand from `examples/i18next`); `test_the_setup_says_fallbacks_are_recorded_and_opens_
     their_review` passes with the line in the panel.

6. **The tests carried over.**
   - `tests/support/tui.py`: `ready()` toggles the targets through their cards (a `pick_targets` helper that finds
     `LocaleCard` by code, searching first when the card is not mounted), then fills the model step as today.
   - The setup's tests in `test_tui.py` that read `#targets` move to the cards. `test_every_field_fits_80_columns`
     checks each step's fields fit when that step is open.
   - → check: `uv run pytest tests/tui` passes, every one of today's 60 tests kept (renamed only where its words
     say "form").

7. **The snapshots** (story decision 006).
   - `test_snapshots.py`: `test_setup` becomes a snapshot of each step (Tree, Targets, Model) at 160×45 and 80×24.
     The Targets one at 80×24 shows the panel under the cards.
   - → check: `--snapshot-update` writes them; each SVG opened and looked at; they pass twice running without it.
     The colours in the new CSS are all theme variables (`grep -n '#[0-9A-Fa-f]\{6\}'` finds none in `setup.py`
     or the kit's new widgets).

8. **The docs.**
   - `docs/guide/getting-started.md`, "Just run it": the setup as three steps, Continue, Esc, ⌃R from any step,
     the cards and their filters.
   - → check: `uv run --group docs sphinx-build -W -b dirhtml docs docs/_build/html` passes.

9. **Everything.**
   - → check: `uv run pytest` (coverage above `fail_under`), `uv run mypy`, `uv run ruff check`, `uv run ruff format
     --check`, `uv run lint-imports`.

## Risks

- **The Run stack's other screens:** `_run` and `_in_run` are unchanged, so the plan, run and review flow is what
  today's tests already prove; they must pass untouched past the setup.
- **`watch_locale_tree`** sets `#tree` on the setup; it must keep the step (step 2's check).
- **Focus:** `AUTO_FOCUS = "#body *"` may land on a hidden pane's widget; each pane's first field takes focus when
  the step opens, checked by the step 1 test pressing a key after a switch.
- **Card churn:** mounting 24 cards on every keystroke of the search may flicker; `_show_targets` runs as an
  exclusive worker, and the test of the search types several letters.
- **The second scan** on every tree change costs one more `ScanLocaleTreeQuery`, the one Home already makes; no new
  query.
